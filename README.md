# TITAN FC — официальный сайт футбольного клуба

Полноценный сайт клуба: публичная часть (3D-стадион, состав на поле, капитаны, статистика,
контакты) + защищённая админ-панель (состав, капитаны, тактика с перетаскиванием карточек, матчи,
статистика, настройки сайта). Всё содержимое хранится в SQLite и управляется из панели — сайт
собирается из данных, которые вы заполняете сами.

**Стек:** React 18 + TypeScript + Vite + SCSS + Three.js / React-Three-Fiber + Lucide React
(фронтенд) · Node.js + Express + SQLite (`node:sqlite`) + multer (бэкенд).

## 2. Быстрый старт

```bash
# 1. Установить зависимости
npm install

# 2. Создать файл конфигурации
cp .env.example .env        # Windows: copy .env.example .env

# 3. Сгенерировать хеш пароля администратора (в .env впишите полученную строку)
npm run hash-password -- ":%67:54*"

# 4. Сгенерировать секрет сессий и вписать его в .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

# 5. Запустить в режиме разработки
npm run dev
```

* Клиент (Vite): <http://localhost:5173> — проксирует `/api` на сервер
* API + собранный клиент: <http://localhost:3001>
* Админ-панель: <http://localhost:5173/admin/login> (или `http://localhost:3001/admin/login`)

> Первый запуск автоматически создаёт `data/titan.sqlite`, папку загрузок и демонстрационные данные
> (14 игроков, капитан и вице-капитан — все помечены словом «Пример», статистика и матчи — нулевые).

### Production-сборка и запуск

```bash
npm run build     # клиент → dist/client, сервер → dist/server
npm start         # один процесс: API + раздача собранного клиента на PORT
```

`npm start` отдаёт и API, и статику (SPA-fallback для `/admin/login`, `/admin/dashboard/...`).

## 3. Доступ в админ-панель

* Адрес: **`/admin/login`**
* Пароль по умолчанию: **`:%67:54*`** (его нужно заменить на свой — см. ниже)

Пароль **никогда** не хранится в открытом виде:

* в `.env` лежит только хеш `scrypt$N$r$p$salt$hash`;
* в базе данных пароля нет вообще — только хеш сессии;
* в React-коде пароля нет — только проверка сессии через `/api/auth/session`.

### Смена пароля

```bash
npm run hash-password -- "новый_пароль"
# → скопируйте строку вида scrypt$16384$8$1$...$... в .env → ADMIN_PASSWORD_HASH
# перезапустите сервер
```

### Что защищено

| Механизм | Реализация |
| --- | --- |
| Cookie сессии | `titan_session`, `HttpOnly`, `SameSite=Lax` (в production — `Secure`), подпись HMAC |
| Хранение сессии | в БД только SHA-256 хеш токена, срок жизни 72 ч (`SESSION_TTL_HOURS`) |
| CSRF | double-submit: cookie `titan_csrf` + заголовок `X-CSRF-Token` + проверка `Origin` |
| Брутфорс | таблица попыток входа: 6 попыток за 15 минут → блокировка на 15 минут |
| Ошибки входа | общий текст «Неверное имя пользователя или пароль» (нет утечки, существует ли аккаунт) |
| Выход | сессия удаляется из БД на сервере (не только чистится cookie) |
| Регистрация | публичной регистрации нет — только вход администратора |
| Админ-API | все `/api/admin/*` закрыты для анонимных запросов (401) |

## 4. Админ-панель: 9 разделов

| Код | Раздел | Возможности |
| --- | --- | --- |
| **A** | Главная | Сводка: игроки, победы, ничьи, поражения, голы, последние матчи |
| **B** | Учительница | Имя, фамилия, подпись («Наш наставник»), фото наставника (загрузка/удаление) |
| **C** | Капитаны | Две карточки (капитан / вице-капитан): фото, флаг, страна, номер, позиция; роли можно менять местами |
| **D** | Игроки | Поиск + фильтр по позиции, CRUD, фото, «в запас / в стартовый состав», назначение капитаном, изменение порядка, подтверждение удаления, контроль уникальности номеров |
| **E** | Тактика | Схемы 4-3-3 / 4-4-2 / 4-2-3-1, **перетаскивание карточек** мышью и пальцем, обмен позициями, авто-расстановка, очистка схемы |
| **F** | Матчи | Добавление матчей, счёт, соперник, логотип соперника, дата, турнир |
| **G** | Статистика | Победы, ничьи, поражения, голы за/против — только те цифры, которые вы вводите |
| **H** | Ценности клуба | Карточки блока «Ценности» на главной: выбор иконки (12 шт.), заголовок, описание, порядок, скрыть/показать, удаление (макс. 6) |
| **I** | Настройки сайта | Название клуба, девиз, подзаголовок, тексты, контакты, соцсети, 5 цветов темы, логотип, режим уникальных номеров, схема по умолчанию |

Все изменения сразу уходят в SQLite и сразу видны на публичном сайте — перезагрузка не нужна.

### Перетаскивание карточек (раздел «Тактика»)

Ровно то, что просили: квадратные карточки игроков можно **двигать мышью или пальцем**:

* карточка с поля → другой квадрат поля → **обмен позициями**;
* карточка с поля → список «Запас» → игрок уходит в запас;
* карточка из запаса → квадрат поля → игрок назначается на позицию (прежний обитатель вытесняется в запас);
* у каждой занятой позиции есть крестик — убрать игрока в запас в один клик.

Дополнительно: авто-расстановка по позициям, очистка схемы, обмен двумя позициями через выпадающие
списки, назначение игрока на позицию без мыши.

## 5. Изображения: загрузка и постоянное хранение

* Форматы: JPG / JPEG / PNG / WebP.
* Ограничение размера: `MAX_UPLOAD_MB` (по умолчанию 6 МБ).
* Проверка типа файла делается **на сервере** по сигнатуре (magic bytes), а не только по расширению.
* Имя файла генерируется сервером (случайное + безопасное расширение), путь не может выйти за пределы
  папки хранения (обход через `../` блокируется).
* Файлы **не хранятся в базе** — в SQLite лежит только ключ вида `players/9f2c….png`;
  отдаются через `/api/media/<ключ>` с проверкой прав.
* Загрузка доступна только администратору; на публичном сайте фото отдаёт тот же защищённый маршрут.

### Вариант A — локальное хранилище (по умолчанию)

```env
STORAGE_DRIVER=local
UPLOAD_DIR=server/uploads
```

Файлы лежат на диске сервера. Подходит для VPS, Docker, любого сервера с постоянным диском.

### Вариант B — S3-совместимое хранилище (Cloudflare R2, MinIO, Yandex Object Storage)

```env
STORAGE_DRIVER=s3
S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com
S3_REGION=auto
S3_BUCKET=titan-fc
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_PUBLIC_URL=https://cdn.example.com/titan-fc
S3_FORCE_PATH_STYLE=true
```

> ⚠️ На Vercel (и любых serverless-хостингах) файловая система **эфемерна**: загруженные фото исчезнут
> при перезапуске/деплое. Для постоянного хранения используйте вариант B (R2/S3) — это единственный
> надёжный способ на Vercel. Локальный диск подходит только там, где есть постоянный volume.

## 6. Переменные окружения

Полный список с комментариями — в `.env.example`. Ключевые:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |

## 9. API (кратко)

**Публично**

```
GET  /api/site            все данные сайта (настройки, наставник, игроки, схемы, матчи, статистика)
GET  /api/health          проверка живости сервера
GET  /api/media/<key>     файл изображения
```

**Авторизация**

```
POST /api/auth/login      вход (пароль) → cookie сессии + CSRF-токен
POST /api/auth/logout     выход (сессия удаляется на сервере)
GET  /api/auth/session    текущая сессия (используется guard'ом /admin/dashboard)
```

**Админ (только для авторизованных, все изменяющие запросы требуют `X-CSRF-Token`)**

```
GET/PUT /api/admin/players        CRUD игроков, загрузка фото
POST   /api/admin/players/:id/bench      отправить игрока в запас
POST   /api/admin/players/:id/starter    назначить в стартовый состав
POST   /api/admin/captains        назначение капитана/вице-капитана
PUT    /api/admin/coach           наставник
POST   /api/admin/uploads         загрузка изображения
DELETE /api/admin/uploads/:key    удаление изображения
GET/PUT/POST /api/admin/lineups…  схемы, расстановка, обмен, авто, очистка
GET/PUT/DELETE /api/admin/matches матчи
GET/PATCH /api/admin/stats        статистика
GET/POST /api/admin/values        ценности клуба (список, добавление)
PATCH/DELETE /api/admin/values/:id  правка/удаление карточки
PUT /api/admin/values/order       порядок карточек
GET/PUT /api/admin/settings       настройки сайта
```

## 11. Ограничения (честно)

1. **Демо-данные помечены как пример** («Пример», «🌐 Страна (пример)») — выдуманных результатов матчей
   и статистики на сайте нет: счёт, победы, ничьи, поражения и голы появляются только после ввода
   данных в панели. Фото наставника и игроков — заглушки с номером, реальные фото загружаются в панели.
2. **Один администратор** с одним паролем; ролей, пользователей и e-mail-восстановления нет.
   Публичной регистрации нет намеренно.
3. На **Vercel** файловая система эфемерна — используйте S3/R2 (раздел 5), иначе загруженные фото
   пропадут после деплоя.
4. Один воркер SQLite: рассчитано на нагрузку любительского клуба. Для больших нагрузок нужна
   PostgreSQL и объектное хранилище.
5. Оптимизация под современные браузеры (Chrome/Edge/Firefox/Safari последних версий); очень старые
   браузеры и Internet Explorer не поддерживаются.
6. Сайт и панель на русском языке; интерфейс админки англоязычный по коду — тексты в UI русские.

## 12. Деплой (кратко)

**VPS / Docker (рекомендуется)**

```bash
npm ci && npm run build
NODE_ENV=production PORT=3001 node dist/server/src/index.js
```

Перед стартом: `.env` с `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, при необходимости `DATABASE_PATH`
(например `/data/titan.sqlite` на подключённом томе) и `STORAGE_DRIVER`.

**Vercel**

* Build: `npm run build`, Output: `dist/client`;
* Serverless-функция: `dist/server/src/index.js` (или отдельный деплой API);
* Обязательно `STORAGE_DRIVER=s3` с R2/S3 и `NODE_ENV=production`;
* база — на внешнем диске (SQLite на serverless-диске не подходит) либо перенос репозитория на
  Postgres при масштабировании.
